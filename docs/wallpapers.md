# 壁紙ライブラリ・tendie・Batter：技術仕様

## 対象と参考実装

- Nuggetの`src/tweaks/posterboard/posterboard_tweak.py`、`tendie_file.py`、`src/gui/pages/tools/posterboard.py`をリビジョン`26e0c50ec114ca3a4ff6ab2fb4ae309abfd39fa1`で参照。
- Nuggetの壁紙パッケージはZIPコンテナで、UI・エクスポートでは`.tendies`という拡張子も使う。本アプリは`.tendie`・`.tendies`・PosterBoard用`.batter`・同じ構造の`.zip`を受け付ける。拡張子だけで安全・対応可能とは判断しない。
- ZIPリーダー・モデル・UI・書き込み制御は独立したSwift実装。Nuggetのソース・素材・テンプレート・SparseRestore / BookRestoreは同梱・実行しない。
- 最初の調査に使ったPosterBoardの私有データ書き出しZIPはアプリに同梱しない。**データ書き出しZIPのインポート対応は廃止**した。端末上の既存データを読み取る機能と、外部パッケージのインポートは別物である。
- 旧版のtendie追加についてユーザーの動作報告あり。今回のライブラリUI・削除・自動更新連携について、開発環境ではmacOSホストテストと実機向けビルドまでを確認し、実機での安全性・反映を保証しない。

## 対応パッケージ

例：

```text
descriptor/
  <パッケージ内の任意の壁紙名>/
    providerInfo.plist
    com.apple.posterkit.provider.descriptor.identifier
    com.apple.posterkit.role.identifier                 # 存在する場合
    versions/
      1/
        contents/
          .com.apple.posterkit.provider.contents.*     # 隠し項目も保持
          com.apple.posterkit.provider.contents.userInfo
          <素材>.wallpaper/
            Wallpaper.plist
            ...素材...
```

認識するパッケージ用フォルダと追加先：

| パッケージ側 | プロバイダー |
| --- | --- |
| `descriptor` / `descriptors` / `ordered-descriptor` / `ordered-descriptors` | `com.apple.WallpaperKit.CollectionsPoster` |
| `video-descriptor` / `photos-descriptor` | `com.apple.PhotosUIPrivate.PhotosPosterProvider` |
| `mercury-descriptor` | `com.apple.MercuryPoster` |

パッケージを囲む通常のフォルダは許可するが、descriptorフォルダより前に`Data`・`Library`・`container`・`Extensions`・`PRBPosterExtensionDataStore`・`configurations`があるコンテナ書き出し系の配置は認識しない。素材内の`Data/`などまで禁止するものではない。

候補には識別子、`providerInfo.plist`、`versions/<非負の番号>/contents/`内のファイルが必要。コピー対象はルートの上記メタデータと`versions/<番号>/contents/`のみで、scratch・DB・設定・RuntimeSnapshot等は取り込まない。

`providerInfo.plist`や`.plist`、userInfo・galleryOptionsはPlistとして構文確認する。NSKeyedArchiver形式でも、`NSKeyedUnarchiver`でクラスを生成しない。CAML・動画・シェーダー等の意味や動作の安全性を検証するものではない。

動画からの壁紙作成、任意のコンテナ復元、壁紙の全消去、SQLiteへの登録・変更は対象外。Batterの対応範囲は次節を参照。

### Batterテンプレート（r5）

[Nugget documentation.md](https://github.com/leminlimez/Nugget/blob/26e0c50ec114ca3a4ff6ab2fb4ae309abfd39fa1/documentation.md)のBatter Files仕様を参照。診断識別子は`wallpaper-gallery-20261115-r5-batter`。形式を独立したSwiftコードで解釈し、NuggetのPython・Qt・復元機構は実行しない。

#### 対象と適用

- `config.json`がちょうど1個必要。`title`・`author`・`domain`・`format_version`・`options`を読み、format 1・2を受け付ける。整数・文字列のバージョン表記に対応。`.zip`等でもconfigがあればBatterとして扱い、未対応の設定を無視して通常のtendieとして適用することはない。
- 対象は`AppDomain-com.apple.PosterBoard`（旧表記`com.apple.PosterBoard`も可）だけ。`Sparserestore-*`、他のAppDomain、`bundle_id`による適用先変更は明示的に拒否する。
- configの親ディレクトリを相対パスの基準にする。通常のdescriptor形式に加え、明示的なBatterの`Container/Library/Application Support/PRBPosterExtensionDataStore/61/Extensions/<対応provider>/descriptors/<名前>/`を読み取る。Container形式でも**新規UUIDの壁紙として追加**し、設定・DB・configurations・元UUIDの復元や上書きはしない。一般のデータ書き出しZIPへの対応を復活させるものではない。
- descriptorフォルダ名には`ordered`・`video`・`photos`・`mercury`をハイフン・アンダースコア・空白で組み合わせられる。既存の標準・Photos・Mercuryの追加先制限を保つ。`ordered`でも新規UUIDで追加し、Nuggetと同じコレクション表示順までは保証しない。
- 複数壁紙を含む場合は1件を選んで追加する。設定はテンプレート全体に対して順番に評価し、その後に選択したdescriptorの許可ファイルだけを取り出す。設定でその壁紙を削除した場合や必須メタデータが不足した場合はエラーにする。
- 適用前の私有ステージングでカスタマイズし、その後に既存のメタデータ構文確認・数値識別子の再割り当て・変更検知・確認付きバックアップ書き込み・自動表示更新準備へ接続する。入力ZIPと差し替え元ファイルは変更しない。

#### 設定項目

| 種類 | 対応内容 |
| --- | --- |
| `replace` | 任意ファイルの選択、`required`、ボタン名、Qtフィルター内の`*.拡張子`によるチェック。同じ内容を複数の対象へ差し替え。 |
| `remove` | ファイル・ディレクトリの削除、チェックの初期値・反転。`identifier`指定時はXML要素を削除。 |
| `picker` | 初期値、単一・複数選択、未選択のファイル削除。単一選択ではファイル・ディレクトリの名前変更。共有される選択済みファイルは削除しない。 |
| `set` | textbox、slider、toggle、color_picker。整数・浮動小数・文字列、範囲、間隔、反転、独自on/off値、RGB / RGBA・opacity。数値は1〜4成分と`scale(…)`等のタグを扱う。 |

XML / CAMLでは`nuggetId`、または`use_ca_id`で`id`と`targetId`を照合して属性を変更する。`nuggetOffset`は`x/y/z/a`、数値、括弧、単項符号、`+ - * / %`に限る有界算術パーサーで解釈する。関数呼び出し、累乗、任意コード、非有限な結果は拒否する。XMLはUTF-8・1 MiB・30,000要素・深さ64までで、DTD・実体宣言・外部実体取得は禁止。CAMLからCoreAnimationオブジェクトを生成しない。名前空間属性と要素のテキスト内容を保持して再出力するが、コメント・処理命令・元の空白や引用形式の完全保存は保証しない。

plistでは同じキーを辞書・配列の中まで辿って変更し、元のXML / binary形式を保つ。その他はUTF-8テキストの文字列置換。対象のidentifier・キー・文字列が存在しない場合は、成功扱いにせずエラーにする。プログラムとして実行することはない。

相対パスは絶対パス・`..`・空要素・リンク等を拒否する。ワイルドカードは`*`・`?`・ディレクトリ成分としての`**`に対応し、隠しファイルも扱う。正規表現への展開ではなく、有界なパス照合を行う。`[文字クラス]`と名前変更元・先のワイルドカードは非対応。名前変更による重複、大小文字・Unicode正規化後の衝突、ファイルと親ディレクトリの衝突を拒否する。

#### 表示・上限・互換性

- タイトル・作者・説明・バナーの文字を表示する。`resources`に含まれる`previews`を最大20件表示し、remove / pickerの`associated_preview`による表示切り替えに対応する。Qtのstylesheet、stacked配置、色・差し替え画像を合成したライブプレビューは実装しない。壁紙候補の素材プレビューもカスタマイズ前の画像である。
- 実機では`min_version`・`max_version`を確認し、範囲外を拒否する。最大`18.0`は`18.0.0`として比較する。
- configは1 MiB、設定200件、1設定の対象指定2,000件、選択肢200件。リソース指定200件、参考画像20件。一度のワイルドカード照合はパターン数×ファイル数2,000,000まで。
- カスタマイズ用仮想ツリーは全体256 MiB・9,000ファイル未満、単一ファイル64 MiB。変更後も同じ制限を確認する。差し替え元はユーザーが選んだファイルをSecurity Scope内で読むだけで、端末ファイルへの権限昇格はしない。差し替えデータのUI保持合計も256 MiBまで。
- ファイルの構文や範囲を検証しても、信頼できないCAML・シェーダー・動画の動作やOSとの互換性は保証できない。実際のOS描画・反映は未検証。対応外の機能や形式ではエラーを表示し、別ドメインへの復元等へ自動的に切り替えない。

### ZIP制限

- 全体1 GiB、50,000エントリー、中央目録16 MiB、候補200件。
- 1壁紙256 MiB、9,000未満のファイル、単一ファイルの圧縮前・後とも64 MiBまで。バックアップの256 MiB・10,000項目・深さ64制限も別途適用する。
- Plistメタデータは単一1 MiBまで。
- UTF-8名、stored（method 0）とraw Deflate（method 8）のみ。Appleのzlibを使用。
- 暗号化、分割ZIP、ZIP64、リンク・特殊ファイル、絶対パス、`..`・`.`、空のパス要素、バックスラッシュ、制御文字、大小文字・Unicode正規化後の重複を拒否する。
- 中央目録とローカルヘッダーの名前・方式・フラグを照合し、範囲・展開サイズ・CRC-32を検証する。ZIP全体を一括でメモリへ読み込まず、選択したエントリーだけを読み取る。
- ファイル記述子・パスのinode、サイズ、mtime、ctimeを読み取り前後で検証し、選択後の差し替えも拒否する。

## コンテナ自動検出

既存の`ApplicationCatalogService`で端末のLaunchServices CSStoreを読み、Bundle IDが厳密に`com.apple.PosterBoard`のApplicationレコードを選ぶ。パスは既存のApplication/UUID検証を通し、実際に構造61の壁紙一覧が読めることを確認する。

複数候補がある場合は読み取り可能な候補を調べ、1件に決められなければ失敗とする。最初のパスを推測で採用しない。パス直接入力、全ボリューム自動走査、端末パスを指定するFilesピッカーは設けない。

書き込み先は次に限定する。親フォルダは既存のものを使う。

```text
<PosterBoardコンテナ>/
  Library/Application Support/PRBPosterExtensionDataStore/61/
    Extensions/<対応プロバイダー>/descriptors/<新規UUID>/
```

コンテナから対象までの各既存ディレクトリを`lstat`し、途中のリンクや非ディレクトリを拒否する。必要な権限だけを共通Managerで取得し、読み取り・書き込みの各処理終了時に解放する。

## 実機上の一覧とプレビュー

`WallpaperLibraryReader`はインポート履歴をそのまま一覧にせず、構造61の`Extensions`内を実際に調べる。安全な`com.apple.*`名のプロバイダーを読み取り対象とするため、インポート対応外の標準壁紙も表示できる。

- **追加した壁紙**：実在するdescriptorと、成功した本アプリの追加記録が一致するもの。
- **ギャラリー**：`descriptors/<UUID>`・`staticdescriptors/<UUID>`・`suggestionDescriptors/<UUID>`に存在する候補。静的・おすすめの候補は読み取り専用で、追加・削除の対象を広げるものではない。
- **保存済み**：`configurations/<UUID>`に存在するロック画面データ。現在選択中という意味ではなく、ここから変更しない。

一覧はファイルシステム上のデータであり、PosterBoardのSQLite登録状態・画面に実際に表示されること・現在の選択を保証しない。OSが残したフォルダが含まれたり、読めない情報が抜けたりする可能性がある。部分的な読み取り失敗は画面に知らせ、ルートの読み取り失敗や上限超過時は成功した一覧として扱わない。

### 名前を列挙できても属性が読めない場合

ディレクトリ一覧で子の名前は取得できても、`URLResourceValues`や子パスの属性取得には別のSandbox Extensionが必要なことがある。共通ファイル一覧の`FileEntry`は属性の先読みが失敗すると、名前を残したまま`isDirectory = false`などへフォールバックする。この値を壁紙走査のフィルターへそのまま使っていた旧実装では、プロバイダーやUUIDフォルダをすべて除外し、エラーなしで0件になり得た。

壁紙走査では先読み済みの型フラグを信用せず、プロバイダー・壁紙・version・素材の各子パスを、Managerの権限再取得付き`lstat`経路で確認する。名前は読めるが属性の先読みだけ失敗する条件、リンクをフォルダと誤表示する条件をホストテストで再現する。リンクや特殊ファイルの拒否は維持する。

属性・一覧・識別子の取得失敗は、操作名・対象パス・エラードメインと番号を最大20件まで収集する。一部が読めた場合は部分結果と警告を表示し、全件を確認できなかった場合は「壁紙なし」ではなく読み取りエラーにする。画面の詳細・コピー操作と操作ログから診断できる。詳細にはコンテナパス等が含まれるため、共有時は個人情報に注意する。POSIX / Cocoaの不存在エラーは、権限拒否と区別する。

### エラーなしで0件になる場合の診断

前の権限対策後も実機で「壁紙はありません」と表示されたため、当時は0件でも診断をコピーできるようにして調査した。調査用のr2から、パス修正後の識別子は`wallpaper-gallery-20261115-r3-pathfix`になった。診断情報のコピー機能は2026-11-16に廃止した。現在は右上メニュー・0件画面・エラー詳細のコピー操作を提供しない。内部の読み取り問題の記録と表示は維持する。

記録するのはOS・アプリ版、選択した表示条件、画面と実データの件数、LaunchServices DB・PosterBoardコンテナ・読み取り先のパス、ストア直下のバージョン名、Extensions直下とプロバイダー直下・候補フォルダの項目数と先頭8名、除外理由（プロバイダー名・非UUID・非ディレクトリ等）。名前の例は120文字、各イベントは1,024文字、イベント数200・UTF-8合計48 KiBで制限し、全体の集計値は別途保持する。壁紙画像やPlistの内容は含めず、外部送信しない。

一覧に出た直後の子パスが`ENOENT`になった場合、単なる「空」とせず、`attribute.enumeratedButMissing`と対象を記録する。削除との競合やOSによる不可視化の可能性があるが、`ENOENT`だけから権限拒否だと決めつけてアクセス規則を緩めない。ストアの別バージョンが見つかっても、自動で書き込み先を切り替えない。

以前の参考データでは標準候補の一部が`staticdescriptors`に存在することも確認できたため、この配置と`suggestionDescriptors`を読み取り一覧へ含める。ただし、後述の実機ログで判明した0件の原因は、この配置の不足ではなくパス表記の混在だった。

### r3：実機診断で判明した `/var` と `/private/var` の混在

r2の実機ログでは、`/var/mobile/Containers/Data/Application/<UUID>/.../Extensions`の一覧取得は成功し、27プロバイダーのディレクトリ属性も確認できていた。一方、そこからのプロバイダー直下と4種類の候補フォルダがすべて`MISSING`となり、`optionalDirectory.missing=135`だった。

Foundationが返した子のURLパスは`/private/var/...`、読み取り開始時のコンテナは`/var/...`だった。旧`validateWallpaperAncestors`は親子関係を確認せずに`path.dropFirst(container.count)`で相対部分を作っていたため、8文字長い子パスを誤った位置で切り、実在しない祖先パスを組み立てていた。プロバイダーの属性確認は別経路で成功するので「27個のフォルダは見つかったが、その先は全部不存在」となり、権限エラーにもならなかった。

修正内容：

- `WallpaperPaths.normalized`で既知の`/private/var`表記だけを`/var`へそろえる。任意のシンボリックリンクの解決は行わない。
- 正規化した対象がコンテナ自身または`container + "/"`の子孫であることを確認してから相対部分を取得する。別コンテナや前方一致するだけの類似パスは拒否する。
- 一覧の子パスは列挙された名前と正規化した親から再構築し、型は引き続き権限取得付き`lstat`で確認する。
- プレビューの範囲確認、壁紙の場所検証、バックアップの出所照合・表示更新履歴のパス比較も同じ表記へそろえる。表記の差で追加済み壁紙を未管理と判定したり、画像・削除・反映案内を拒否したりしない。
- 共通ファイルブラウザー全体のパス規則やアクセス許可範囲は変更しない。実体の異なるリンク・範囲外の拒否は維持する。

`Tests/WallpaperPathTests.swift`は、`/var`で列挙を開始し、すべての子URLが`/private/var`で返る実機と同じ条件を再現する。旧祖先チェックでは1プロバイダーにつき5件が`MISSING`となり一覧0件になることを確認し、実運用と共通の正規化・子パス・祖先構築を使う修正版ではギャラリーと保存済みの2件を取得し、追加記録・プレビューのパス・更新成功履歴も照合できることをテストする。これは実機の描画・削除操作自体の検証とは別である。

最大2,000壁紙、走査した項目合計30,000まで。各壁紙の最新の数値versionのcontentsだけを深さ16まで調べ、scratchやキャッシュへ再帰しない。リンクを辿らない。表示名は追加時の保存名、素材の`.wallpaper`名、識別子の順で復元する。

プレビューはcontents内のPNG / JPEG / HEIC / HEIFからthumbnail・preview・background等を優先して選ぶ。読み取りは16 MiBまで、ImageIOで長辺480 px以下へ縮小しPNGとしてメモリに保持する。描画は遅延グリッド内の可視セル等で読み込み、CAMLや私有のATX / cpbitmapは描画しない。素材単体なので、ロック画面の合成、色、時計、奥行き、アニメーションの再現ではない。取得できないものは「プレビューなし」とする。

## 追加記録と削除の境界

追加時に新しいUUIDを作る。既存フォルダの置換・結合はしない。Collectionsの数値識別子と対応するuserInfo・Wallpaper.plistの識別子を再割り当てし、Mercury / Photosの意味を持つ文字列識別子は保持する。

永続的な出所判定には既存のバックアップを使う。別のファイル名や壁紙名が同じだけでは本アプリの壁紙として扱わない。`FileBackupRecord`の次の条件をすべて確認する：

1. `operationKind == addWallpaper`。
2. `outcome.succeeded == true`。
3. 記録された追加先パスと現在のdescriptorのパスが一致。
4. 作成後に記録したルートディレクトリと、現在のルートのdevice / inodeが一致。

旧版の成功した追加記録も上記で照合する。新しい記録には`manifest.json`の省略可能な`wallpaper`メタデータ（表示名、元パッケージ名、変更ID、表示設定側かどうか）を付ける。これがない旧manifestも読める。

削除はdescriptorだけ。標準壁紙、他ツールの壁紙、記録のない壁紙、configurationsは削除不可。確認準備時と実行時に出所とパスを再照合する。別のフォルダへ置換されていれば拒否する。

OSが内部ファイルやキャッシュを更新しても同じ追加先ルートであれば、明示的な削除を許可する。この点は既存の「バックアップから追加操作を取り消す」と異なる。削除は**現在の内容全体を改めてバックアップ**し、コピーと内容検証に成功してから行う。リンク・特殊ファイルやバックアップ制限違反は拒否する。

削除バックアップは通常の復元機能から元のパスへ戻せる。復元でルートのinodeが変わった場合は、古い追加記録だけで同じ出所だと推定しない。バックアップを失った場合も所有の推定はしない。アプリを削除するとアプリ内バックアップも失われる。

## 表示更新を追加・削除と一体化

Nuggetの`apply_tweak`は`force_pb_refresh`有効時、壁紙の適用と同じ処理で表示更新用の設定を追加する。本アプリも「いつフラグを設定するか」を利用者に判断させず、追加・削除の確認に表示更新準備を含める。

変更する設定：

```text
Library/Preferences/com.apple.PosterBoard.unprotectedUserDefaults.plist
  PBF_RESET_FILE_PROTECTIONS = true
  PBF_LOCALE_DID_CHANGE = false
```

元のXML / binary形式とその他のキーを保持し、既存inodeへ保存する。設定ファイルがない、Dictionaryでない、上限超過、読み書きできない場合は壁紙を変更する前に中止する。

Nuggetは26.4以降で`PersistedPosterContainerBundleIdentifiers`や`CompletedPosterBundleIdentifierMigrations`も所定の値で作成する。一方、本アプリは端末の既存設定を直接編集するため、これらをNuggetの復元用固定値へ置き換えない。Nuggetの設定ファイル全体の置換やconfigurations登録方式をそのまま移植したわけではない。OSによってdescriptor方式が維持されない・表示されない可能性は残る。

### 書き込みの順序

`WallpaperWriteTransaction`を共通Managerの排他的なアクセスセッション内で実行する。

1. 共通Yes / No確認を一度だけ消費。
2. 追加先の不存在、または削除対象の出所を検証。
3. 表示設定の元データを再検証し、変更しない`O_RDWR` openで書き込み可能性を確認。
4. **壁紙操作と表示設定の両方の永続バックアップ**を先に完成させる。
5. 再度preflight・スナップショットを照合。どちらかのバックアップ失敗や事前の外部変更では、どちらも書き込まない。
6. 壁紙を追加／削除し、壁紙側の成功記録を保存。
7. 表示設定を書き込み、表示設定側の成功記録を保存。

同じ変更IDで2つのバックアップを関連付ける。自動ロールバックや、端末全体をロックするトランザクションではない。外部プロセスによる同時変更・強制終了は完全に防げない。

壁紙の変更後に設定保存だけが失敗した場合、壁紙側の成功記録を失敗で上書きしない。エラーに部分成功を明示し、次の一覧読み取りで「表示の更新をやり直してください」と案内する。「表示を更新」は設定側だけをバックアップ付きで再試行し、壁紙を重複追加・再削除しない。

コピー自体が途中で失敗した場合は、部分的なフォルダが残る可能性がある。完了を証明できないフォルダを管理対象として自動削除することはしない。バックアップとログを保持する。

### リスプリングと案内状態

設定保存はOSの即時反映を確認するAPIではない。成功後は「リスプリングして反映」を案内し、利用者が作業を保存してから既存のリスプリング機能へ進む。自動実行はしない。

完了した壁紙操作・表示更新のバックアップ日時を、アプリ内の「ロック画面で確認しました」の日時と比較して案内カードを表示する。これは利用者が確認するための状態であり、OSの選択状態や実際の反映を推測するものではない。OSがフラグを消費しただけで「未更新」と誤判定することもしない。

通常は追加・削除で更新準備が終わるため、別の設定操作は不要。表示されない場合の再試行は「…」→「壁紙が表示されない場合…」にまとめる。

## 非同期と一時データ

一覧モデルは読み込み世代を管理し、古い成功・失敗やバックグラウンド移行後の結果を採用しない。追加・削除の確認準備にも世代を設け、破棄後に届いた要求はManagerでキャンセルする。

### 写真・ビデオの表示と一覧キャッシュ

写真・ビデオのプロバイダー`com.apple.PhotosUIPrivate.PhotosPosterProvider`は初期状態で全カテゴリの一覧から非表示にする。右上メニューの「写真・ビデオを表示」で切り替え、設定はAppStorageに保持する。非表示は削除や走査対象からの除外ではない。元の一覧には項目を保持し、ON/OFFや検索・カテゴリ切り替えだけでは端末を再走査しない。

`WallpaperLibraryModel`は`AppModel`に保持し、壁紙画面の生成・破棄をまたいで完了した一覧を共有する。正常に完了した一覧だけを、完了から180秒・同じ`fileWriteRevision`の間再利用する。タブ移動・詳細シートを閉じた際・バックグラウンドから戻った際に有効なキャッシュがあれば、一覧走査とコンテナ再探索を省略する。ファイルタブでの閲覧・移動だけでは書き込み世代を進めず、キャッシュを失効させない。画面を開いたままの定期ポーリングは行わない。キャッシュは一覧メタデータのメモリ内保持で、写真素材やプレビューをディスクへ永続化するものではない。アプリ再起動では失われる。

「一覧を更新」、下に引く更新、中止後の「再開」、エラー後の再試行はキャッシュを無視する。アプリ内の書き込み・復元等で`fileWriteRevision`が変わった場合も再読み込みする。追加・削除・表示更新の準備では事前にキャッシュを無効化し、途中失敗やNoでも次回に読み直す。無効化の世代を持ち、無効化前に開始した読み込みが後から完了しても、その結果を新しい有効キャッシュとして登録しない。

部分結果・失敗は有効キャッシュにしない。更新中の既存グリッド保持とキャンセル処理は従来どおり維持する。キャッシュを使った表示から操作する場合も、実際の書き込み時には既存のパス・出所・inode・外部変更検証を改めて行う。キャッシュは書き込み権限や最新状態の証明には使用しない。iOSや別アプリによる変更は有効期間内には自動検知しない場合があるため、必要なら手動更新する。

`Tests/WallpaperCacheTests.swift`で有効期間、強制更新、ファイル変更世代、明示的な無効化、途中結果・失敗の拒否、走査中の無効化、時刻の逆行、写真・ビデオの既定非表示と表示切り替えを確認する。

### r4：他の画面・ファイル操作を待たせない読み取り

以前は`await`でUIから呼び出していても、`FileAccessManager`内の1回の同期処理で全フォルダを走査していた。その間は同じManagerを使う別タブの読み書きが待たされた。r4（診断識別子`wallpaper-gallery-20261115-r4-async`）では次のように分離した。

- `WallpaperLibraryWorker` actorで走査と表示名・診断情報の構築を行う。UI actorでは実行しない。
- 一覧取得・属性取得・識別子の読み取りはそれぞれ独立した非同期I/O要求として共通Managerへ送る。バックアップ履歴も一括で全件を解析せず、ID一覧取得後に1記録ずつ読む。
- 各I/O要求の中だけでアクセスセッションを開始し、その要求の終了時にSandbox Extensionを解放する。**セッション内ではawaitしない**。worse_queryや書き込みを並列実行せず、要求の間に他タブの読み書きを実行できるようにする。
- フォルダ一覧では名前だけを取得し、不要な全件属性先読みは行わない。型はこれまでどおり子パスごとの権限確認付き`lstat`で確認する。r3の`/var`・`/private/var`の統一、コンテナ範囲・リンク拒否も維持する。
- 端末上のプレビュー画像のファイル読み取りとImageIOの縮小・PNG化を分離し、ImageIOは専用actorで直列実行する。画像処理でファイルアクセスManagerを占有しない。
- 全一覧の整列が終わる前でも、最初の1件、以後8件ごとまたは約150 msごとを目安に部分結果を公開する。初回は取得できたカードから表示する。再読み込みでは前回のグリッドを保持し、途中の1・8・16件で置き換えてちらつかせない。最終結果だけを完了状態として採用する。
- コンテナの特定はExtensionsを列挙できる候補が1つかどうかで先に検証する。その後に詳細を走査するため、一覧全体を待たずにtendie選択を開始できる。

読み取りTaskはutility優先度で起動し、モデルが実際のTaskハンドルも保持する。再読み込み・「中止」・タブ移動・シート表示・書き込み開始では読み取りTaskをキャンセルし、別タブ操作や書き込みを優先する。バックグラウンド移行時は従来どおり確認要求とアクセス状態も破棄する。キャンセル済みの画面Taskが遅れて新しい読み込みを取り消さないよう、開始前にもキャンセル状態を確認する。

部分一覧を保持して中止した場合は途中の一覧だと明示し、「再開」で読み直す。完了前の結果を正常完了と誤認しない。すでに実行中の1回のOSファイル操作・権限取得・書き込みを途中で強制中断するものではなく、キャンセルはその操作の境界で反映する。走査全体はファイルシステムの原子的スナップショットではないため、間に変更されたファイルは既存の変更検知・エラー表示で扱う。

`Tests/WallpaperAsyncTests.swift`では、走査を部分結果の通知箇所で止めたままMainActorの操作、および同じFileAccessManagerでの別ファイルの読み取り・確認付き保存が完了することを確認する。実際のTaskキャンセル、後続I/Oの停止、途中表示、前回一覧の保持、遅れた進捗の拒否もテストする。実機の応答時間は未計測である。

インポート元のSecurity ScopeはZIPを読み取る間だけ有効にする。確認前の展開は専用の一時フォルダ内だけで行い、通常のキャンセル・完了・失敗・アクセス状態破棄で削除する。プロセス強制終了時の即時削除は保証しない。素材・履歴・端末パスは外部送信しない。
