# アプリ・App Groupsの読み取りキャッシュ

## 使用時の動作

- アプリ一覧とApp Groupsの探索完了結果を、**アプリを終了するまでメモリ内で再利用**する。
- キャッシュは`AppModel`が保持するサービスactorに各1件あり、画面の破棄・再生成、タブの切り替え、バックグラウンドからの復帰をまたいで共有する。アプリ再起動で消える。
- 再読み込みするのは、**まだキャッシュがないとき**、またはユーザーが明示的に更新したときだけ。
  - アプリ一覧の「一覧を更新」「DBを再検索」
  - App Groupsの「更新」（下に引く更新も含む）
- 画面を開き直すだけ、タブを戻るだけ、ファイルの閲覧や書き込みの後では再読み込みしない。時間経過による自動失効もしない。
- ファイルやUserDefaultsへ一覧・探索結果を保存しない。従来どおり前回のDBの場所だけを設定に保存する。
- キャッシュ上で「開ける」と表示されても、実際に開く際は通常のアクセス確認を行う。

## 層との関係

- 中位層の`ApplicationsView`と`AppGroupsView`は`AppModel.applicationCatalog` / `AppModel.appGroupScan`を共有する。
- 最上位層（壁紙・キーパッド・LINE）がアプリ一覧を必要とする場合も、`AppModel.loadApplications()` / `scanAppGroups()`を通す。初回だけ読み込み、以降は同じキャッシュを使う。
- App Groupsの探索は、同じアプリ一覧スナップショットを入力にする。アプリ一覧を明示更新した場合はDBが変わり得るため、App Groupsのキャッシュも同時に破棄する。

## 再利用する処理とキー

`ApplicationCatalogService`はDBの発見・読取り・CSStore解析を終えた`ApplicationCatalogSnapshot`を保存する。キーは使用する署名App Group。キャッシュが有効ならDBファイルへのI/Oを行わない。

`AppGroupScanner`は候補列挙・フォルダ/管理情報確認まで完了した`AppGroupScanSnapshot`を保存する。キーには正規化・重複除去した既知パス、DB解析結果、DBスナップショットの`loadedAt`を含む。明示更新では既存キャッシュを破棄してから読み直す。

## 完了・失敗・キャンセル

キャッシュは`SessionReadCache`が保持する。無効化時に世代トークンを発行し、以前の読み取りが後から完了しても新しいキャッシュを上書きしない。

実行途中の結果・キャンセル・throwされたエラーは保存しない。強制更新は既存キャッシュを先に破棄し、失敗時に古い一覧を新しい結果として返さない。App Groupsは一部の権限警告や親を列挙できない空一覧も含め、正常完了した結果を警告ごと保存する。DB読取り失敗の結果だけは再試行できるよう保存しない。

キャッシュするのは一覧情報だけで、ファイルハンドルやSandbox Extensionの権限を保持するものではない。バックアップ・編集・削除・ZIPエクスポート等の安定読み取り、対象検証、外部変更チェックは省略しない。

## テスト

`Tests/ApplicationReadCacheTests.swift`ではアクセスactorを差し替え、以下をホスト上で検証する。

- キャッシュが明示的な無効化まで再利用されること。
- アプリ一覧のヒットでDB解析を行わないこと、署名グループ・強制更新・再検索で失効すること。
- App Groupsのヒットで候補列挙・管理情報・署名照合・部分進捗が再実行されないこと。
- パス別名の統一、DB内容の変更、権限警告の保持、DB失敗の再試行、親を列挙できない空一覧の再利用。
- キャンセルした部分結果の除外と、古い読み取り完了による新しいキャッシュの上書き防止。

実機のOSや他アプリを操作するテストではない。
