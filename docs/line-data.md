# LINEデータのビューワー

LINEのトークは、ホームの「LINEビューア」から表示します。

**ホームの「LINEビューア」**：開くとLINEの共有フォルダ（`group.com.linecorp.line`）を自動で検出し、トーク一覧をそのまま表示します。表示元を選ぶ画面はありません。`group.com.linecorp.line`がない場合は、`group.com.linecorp`で始まるグループの順で自動的に選びます。

開いた後の表示・検索・安全対策は共通です。

## 対応するデータ

共有フォルダ直下の`Library/Application Support/PrivateStore/P_<アカウントMID>/Messages/`にある、次のSQLiteデータベースを読み取ります。

| DB | 用途 |
| --- | --- |
| `Line.sqlite` | トーク一覧（ZCHAT）・メッセージ（ZMESSAGE）・ユーザー名（ZUSER）・グループ名（ZGROUP）・メンバー（Z_1MEMBERS） |
| `UnifiedGroup.sqlite` | グループ・複数トークの名前（ZUNIFIEDGROUP）。`Line.sqlite`の`ZGROUP`を補完 |
| `MessageExt.sqlite` | メッセージへのリアクション（ZMESSAGEREACTION） |
| `LineSquare.sqlite` | オープンチャット（ZCHAT / ZSQUAREMEMBER / ZMESSAGE / ZMESSAGEREACTION） |

- 各DBの隣接する`-wal`も一緒に複製します。`-shm`は複製しません（SQLiteが再構築するため）。
- アカウントのMIDはPrivateStoreフォルダ名（`P_<MID>`）から判定します。複数アカウント分のデータがある場合は、名前順で最初の1アカウントだけを対象にします。
- トークとオープンチャットの両方が存在する場合、画面上部のセグメントで切り替えられます。`Line.sqlite`に複製されたオープンチャットはトーク一覧から除外し、`LineSquare.sqlite`側で名前・メッセージを表示します。名前もメッセージもない空のトークは一覧に表示しません。
- `ZCHAT.ZTYPE`は`0`=1:1、`1`=複数人トーク、`2`=グループ、`100`=自分へのメモです。古いDBの`4`も複数人トークとして扱い、`ZTYPE`が不明な場合はMIDの接頭辞（`c…`=グループ、`r…`=複数人トーク）で補います。
- `Line.sqlite`の`ZGROUP`を優先し、名前が空の場合だけ`UnifiedGroup.sqlite`の`ZUNIFIEDGROUP`で補完します。どちらもない場合は`Z_1MEMBERS`のメンバー名を連結します。

## 端末から直接読み取る場合

- 検出は**内容ベース**です。グループIDに関わらず、`Library/Application Support/PrivateStore/P_*/Messages/Line.sqlite`が実在する共有フォルダだけを対象にします。候補はスキャン結果のうち`group.com.linecorp`で始まるグループIDを持つものです。
- フルサイズの添付は、LaunchServices DBから`jp.naver.line`のデータコンテナを特定し、`Library/Application Support/PrivateStore/P_<MID>/Message Attachments`を直接読み取ります。共有フォルダ側のMIDと同じアカウントを使います。
- App Groupのパスは`AppGroupPaths.container`で正規化・検証し、App Groupルート外のパスは受け付けません。
- **サブフォルダの一覧・ファイルの属性確認・読み取りごとに、共通Managerの権限再試行を実行します**（アプリデータのエクスポートと同じ方式）。共有フォルダのルートが読み取れても、その配下の`Library/Application Support/PrivateStore`等はOSに拒否されることがあるためです。権限拒否は「DBなし」ではなくエラーとして表示します。
- ファイルはAPFSの`clonefile`で複製し、使えない場合だけ`StableFileReader`と同じ方式（リンク拒否・コピー前後のinode・サイズ・時刻照合）のストリームコピーへ切り替えます。**LINEを終了してから**開いてください（どちらの方式でも、複製中にDB・WALが変わった場合は「LINEを終了してから開いてください」のエラーを表示します）。
- 権限不足で一覧できない場合のみ、既存の共通Managerがそのパスの権限取得を試みます。探索・検出・複製のいずれも元データへの書き込みはありません。

## 表示内容

- **トーク一覧**: 名前と最終更新日（yyyy/MM/dd）。名前は次の順で決まります。
  1. 1:1トーク → 相手ユーザーの名前（`ZUSER`）
  2. グループ・複数トーク → `ZGROUP`の名前。なければ`ZUNIFIEDGROUP`、それもなければメンバー名の連結（最大3名＋他N人）
  3. 自分（`ZTYPE=100` または自分のMID）→ 「自分」
  4. いずれも不明 → 「（名称不明）」
- **メッセージ**: 100件単位で新しい順に読み込み、画面を開くと最新位置から表示します。「過去のメッセージを読み込む」で古いページを先頭に追加します。自分のメッセージは時刻を吹き出しの左外側に、相手のメッセージは時刻を吹き出しの右外側に表示します。日付が変わる位置には中央に小さく年/月/日を表示します。
- **メッセージ検索**: トーク内で2文字以上の語を入力すると、本文（`ZTEXT`）にその語を含むメッセージをSQLiteの`LIKE`で検索し、最大500件を新しい順に表示します。検索中は会話表示と切り替わります。`%`・`_`・`\`はエスケープします。
- **負荷対策**: 画像は表示された行だけ遅延読み込みし、画面外に出た行の画像は解放します。読み込んだ画像は表示サイズに縮小し、メディアキャッシュは件数・容量の上限内で保持します。古い履歴を遡ったときは、保持するメッセージを最大2,000件に制限し、超過後は「最新のメッセージに戻る」から最新位置を再読み込みできます。
- **既読**: 自分のメッセージの下に既読数を表示します（`ZMESSAGE.ZREADCOUNT`。列がない古いDBでは「未読」）。1:1トークは「既読／未読」、グループ・複数トークは「既読 N」です。タップすると「既読した人」を表示します。LINEは既読数だけを端末に保存し、既読した人の名前は保存しないため、全員既読と分かる場合だけメンバー名を並べ、それ以外は既読数とメンバー一覧を表示します。古いDBに`ZREADCOUNT`がない場合も、メッセージ表示自体は失敗しません。
- **吹き出し**: 自分のメッセージ（`ZSENDER`がNULL）を右側、相手を左側に表示します。通話履歴・プレゼンス・アルバム追加などの通知・グループ参加/退出（`ZCONTENTTYPE` 6/8/16/18）は中央に灰色で表示します。取り消し通知などはメタデータの`systemMessageTypeName`でも判定します。スタンプ画像を取得できた場合は、スタンプのメタデータを吹き出し内に表示しません。
- **リアクション**: `MessageExt.sqlite`（オープンチャットでは`LineSquare.sqlite`内）の`ZMESSAGEREACTION`を集計し、カスタム絵文字ごとに件数と自分が含まれるかを表示します。`ZCUSTOMREACTION`が空の場合は`ZREACTIONTYPE`（2=NICE、3=LOVE、4=FUN、5=AMAZING、6=SAD、7=OMG）を絵文字に変換します。
- **メッセージ詳細**: 長押し→「詳細を表示」で、種類・日時・送信者・メッセージID・本文・リアクションの反応者・メタデータの生のキーと値を確認できます。
- **メディア一覧**: トーク一覧またはトーク画面のツールバーから、画像・動画・ファイル・スタンプを新しい順に一覧表示します。トーク一覧からはアカウント全体、トーク画面からはそのトークだけを対象にし、「すべて / 画像・動画 / ファイル / スタンプ」で絞り込めます。100件ずつ読み込み、画像・スタンプはサムネイルから詳細と共有ができます。ファイル・動画の本体は共有フォルダにないため共有できません。

### コンテンツタイプ

`ZCONTENTTYPE`は実データで確認できた値に合わせています。`0`〜`22`の一部はLINEのThrift `ContentType`と一致しますが、iOSはFlexを`5`、位置情報を`100`、公式アカウントの画像を`96`、複数メッセージのまとめを`111`、その子メディアを`112`として保存するため、プロトコル定義だけでなく実際のDBの値で判定しています。未確認の値は「種類 N」として本文・メタデータごとそのまま表示します。

| 値 | 表示 |
| --- | --- |
| 0 | テキスト |
| 1 / 2 / 3 | 画像 / 動画 / 音声 |
| 4 | HTML |
| 5 | Flex（`FLEX_JSON`・`FLEX_VER`・`indexableText`） |
| 6 | 通話履歴（中央表示、`DURATION`） |
| 7 | スタンプ（`STKPKGID` / `STKID` / `STKTXT`、ローカル画像を表示） |
| 8 | プレゼンス（中央表示） |
| 9 | ギフト |
| 10 | グループボード |
| 11 | アプリリンク |
| 12 | リンク |
| 13 | 連絡先 |
| 14 | ファイル（`FILE_NAME`・`FILE_SIZE`、PDF/XLSX等） |
| 15 | 位置情報 |
| 16 | アルバム（`albumName`・`mediaCount`） |
| 17 | リッチメッセージ（`ALT_TEXT`・`MARKUP_JSON`） |
| 18 | グループ参加・退出などのシステム通知（中央表示） |
| 19 / 20 / 21 | 音楽 / 支払い / 拡張画像 |
| 22 | Flexメッセージ |
| 96 | 公式アカウントの画像（サムネイル/添付を表示） |
| 100 | 位置情報（`ZTEXT`の住所） |
| 107 | URLリンク/プレビュー |
| 111 | まとめ（`GTOTAL`・`subMessageIds`） |
| 112 | まとめ内の画像メディア（`FILE_SIZE`・E2EE情報） |

`ZCONTENTMETADATA`はNSKeyedArchiver形式のバイナリplistのため、`NSKeyedUnarchiver`で辞書に復元します。セキュアコーディング形式と従来形式の両方を読み、ネストした配列・辞書も件数と深さを制限して文字列化します。既知のキー（`FILE_NAME`・`FILE_SIZE`・`STKID`・`STKTXT`・`DURATION`・`ALT_TEXT`・`FLEX_VER`・リンク関連・`LATITUDE`/`LONGITUDE`・`REPLACE`・`MENTION`・`replyOriginalMessageId`など）は読みやすい行にし、復元できない場合も本文の表示には影響しません。

### 返信・メディア

- **返信スレッド**: `ZCONTENTMETADATA`の`replyOriginalMessageId`（スタンプ等では`message_relation_server_message_id`）を返信先として解決し、吹き出しの上に送信者と本文のプレビューを表示します。詳細画面では返信先のメッセージIDも確認できます。
- **画像・動画のサムネイル**: `Message Thumbnails/<chatMID>/<messageID>.thumb`（実体はJPEG）を共有フォルダから読み込みます。
- **フル画像・添付ファイル**: `Message Attachments/<chatMID>/<messageID>.<拡張子>`は`jp.naver.line`側のアプリコンテナにあります。アプリ一覧のLaunchServices DBから`jp.naver.line`のデータコンテナを特定し、画像・動画・PDF・音声・ファイル本体を直接読み取って表示・共有します。フル画像は画面にフィットして表示し、ピンチ操作で拡大・縮小、ダブルタップで拡大切り替えができます。アプリコンテナを読み取れない場合は、サムネイルとスタンプのみ表示します。
- **スタンプ画像**: `Sticker Packages/<pkg>.<ver>.linestk/<stkid>@2x.png`と`Stray Sticker Packages`のPNGを共有フォルダから読み取ります。
- メディアは要求された1件だけを共有フォルダまたは添付ZIPから読み込み、メモリ上に上限付きでキャッシュします。添付ファイルは一時ファイルへ取り出してから共有します。
- **メディア一覧**: 画像・動画・ファイル・スタンプのメッセージをページ単位で一覧します。画像・スタンプは`Message Thumbnails`・`Sticker Packages`から読み込みます。動画・ファイル・PDF・音声は、`jp.naver.line`のアプリコンテナから「共有 / 別のアプリで開く」で開けます。共有時だけ`LINEMediaShare-<UUID>`へ一時コピーを作成し、シートを閉じると削除します（強制終了時はキャッシュ整理の対象）。ツールバーの「…」→「表示」→「サムネイルも元ファイルもない画像を隠す」は既定でオンです。共有フォルダのサムネイルがある画像は表示し、アプリコンテナのフルサイズ（元ファイル）がない場合は「元ファイルなし」のバッジを付けます。元ファイルだけがある画像は元ファイルを縮小して表示します。サムネイルも元ファイルもない画像だけを隠します。権限不足で存在を確認できない画像は、未存在と断定せずバッジを付けずに表示します。

## セキュリティ・安全対策

- 表示に必要なDBのみを`tmp`の`LINEDataPreview-<UUID>`（0700）へ複製します。APFSの`clonefile`が使える場合はcopy-on-writeの複製なので、数GBのDBでも追加の読み取りとディスク消費はほぼ発生しません。元の共有フォルダには書き込みません。
- `jp.naver.line`のアプリコンテナはLaunchServices DBのデータコンテナだけを対象にし、`Message Attachments`の一覧・読み取り・コピーごとに共通Managerの権限再試行を実行します。元のアプリコンテナには書き込みません。
- コピー先のファイル名はDBの役割名で固定し、共有フォルダ内のパスがコピー先に影響しない構造です。
- メインDB（`Line.sqlite`）を最初に複製し、ヘッダーが`SQLite format 3`であることを確認してから残りを複製します（暗号化DB・なりすましファイルの誤読防止）。リンクは検出・複製のいずれでも拒否します。
- 複製合計の上限は**3 GiB**、クエリ実行時間は1件約10秒までです。`clonefile`を使った場合は上限判定だけに使い、実ディスク消費は元との差分だけです。
- SQLiteは`SQLiteDocument`と同じ制限付きの読み取り専用接続（`query_only`・`trusted_schema=OFF`・オーソライザー・`NOFOLLOW`・中断検出）で開き、**ステージングの複製だけ**を対象にします。
- 端末内のE2EEメディアはLINEが復号済みの平文（JPEG/PDF等）で保存しているため、そのまま表示します。暗号化されたblobがローカルに残る場合の復号は行いません。詳細は[line-e2ee.md](line-e2ee.md)。
- メディアは共有フォルダまたは添付ZIPから必要な1件だけを読み取り、リンク・特殊ファイル・読み取り中の変更を拒否します。
- ビューアをナビゲーションから閉じるとステージングフォルダを削除します。トークを開いている間は削除しません（トークから一覧へ戻ったときに一覧を再読み込みできるようにするため）。強制終了時に残ったフォルダは、起動時の24時間経過チェックと「設定」→「ストレージ」→「キャッシュの整理」（`LINEDataPreview-*`・`LINEMediaShare-*`）が対象にします。

## 制限

- LINE公式の形式文書は存在しないため、構造は実際のデータ（Core Data形式の`Z`接頭辞テーブル）から逆引きしたものです。LINEのバージョンによってテーブル構成が変わると表示できない場合があります。その場合は「…」→「SQLiteで表示」で生DBを確認できます。
- トーク名・メンバー名はDBに保存されている値を使用します。連絡先が同期から外れている場合などは「（名称不明）」になります。
- 既読はLINEが端末に保存する既読数（`ZREADCOUNT`）だけを表示します。グループで誰が読んだかの内訳は端末に保存されていないため、全員既読と分かる場合を除いて名前は特定できません。
- 動画の再生・音声の再生・PDFのページ表示には対応していません（サムネイル、ファイル名、サイズ、長さを表示します）。E2EE鍵データ（`E2EEData.sqlite`）は読み取りません。
- フル画像・添付ファイルは`jp.naver.line`側のアプリコンテナにあり、LINEの共有フォルダには含まれません。アプリコンテナを読み取れない場合は、サムネイルとスタンプのみ表示します。
- この機能は端末上の読み取り専用表示です。データの書き戻し・LINEアプリへの反映は一切行いません。
