# 電話のキーパッド画像：対応範囲と安全対策

## 参考

- [AirCard](https://github.com/Mak5er/AirCard/tree/52ba05dca4bdc590672c19d554701f4438e20338)：README、`aircard_backend.py`の`.passthm`形式とロック画面キャッシュの命名。
- [Erosion](https://github.com/jailbreakdotparty/Erosion/tree/fb16225faa120d258ca5b8856568cf504199598f)：`Tweaks/Keypads/KeypadManager.swift`・`KeypadView.swift`の電話アプリ側の対象、外観別ファイル、画像調整と反映手順。

Swiftのテーマ読み取り、画像処理、パス検証、非同期読み取り、UI、一括バックアップ／書き込みは独立した実装。参照先のソース・テーマ・画像・Python・AirLift／AirTraffic／圧縮抽出ツールは同梱・実行しない。アクセスは本アプリの共通`FileAccessManager`と既存のworse_queryを使用する。AirCardのAirLift対応OS範囲を、このアプリの対応範囲や動作保証として流用しない。

## 使い方

1. ホームの「キーパッド編集」を開く。
2. 電話アプリの画像を自動で読み取る。読み取りは非同期で、他のタブへ移動できる。適用先の切り替えはない。
3. `.passthm`を読み込むか、数字・`*`・`#`をタップして画像を選ぶ。個別画像はテーマの同じキーより優先する。画像がないキーは変更しない。
4. 必要なら「円形に切り抜く」を選ぶ。画像はテーマや選択画像の寸法に関係なく、端末の各既存PNGの幅・高さへ自動調整する。固定サイズ・カスタムサイズの指定はない。変更したキーだけが対象になる。
5. 「変更を確認して適用」→共通確認画面のYesを選ぶ。Noや画面終了では保留中の要求を破棄する。

パスコード、Face ID、認証動作、キーの入力先・数字との対応は変更しない。数字を含む任意のファイル名からキーを推測せず、定義した画像名だけを認識する。アプリはパスコードの入力を求めたり、保存したりしない。

**実機での安全性・表示反映は未検証。** 使用前に端末をバックアップし、パスコードを確実に確認する。設定によって視認性が低下する可能性がある。OSのキャッシュ再生成・OS更新でデザインが失われる場合があり、永続性を保証しない。

## 対象の自動検出

ロック画面のキーパッド機能は2026-11-16に削除した。選択UI・読み取り・書き込み・保存の対象は電話だけに限定し、`/var/mobile/Library/Caches/TelephonyUI-8`・`9`・`10`とその`/private/var`別名はキーパッド用APIで拒否する。過去の保存画像や永続バックアップは削除しない。

既存のLaunchServicesカタログから、Bundle IDが厳密に`com.apple.mobilephone`のApplicationを選ぶ。Application/UUIDのデータコンテナ候補が1つに決まる場合だけ、次を読む。

```text
<電話アプリのデータコンテナ>/Library/Caches/TelephonyUI-10
```

パスの直接入力や全領域走査はない。フォルダが未生成なら電話のキーパッドを開き、外観を切り替えてから再読み込みする。iPad等で電話アプリ・対応データが確認できない場合は適用しない。端末にない画像・言語別ファイルの生成、`_big`・`_small`の配置、CPBitmapの変更、キャッシュ全体の削除は行わない。

「確認済み」の直下に「ファイルビューワーで開く」を配置する。読み取りに成功したフォルダが1つに確定した場合だけ有効になり、既存の`AppModel.browse`でそのフォルダをファイルタブへ開く。フォルダが空でも読み取り成功なら開けるが、場所が未確認の場合は無効にする。ここからファイルを編集・削除する場合もファイルビューアーの共通確認・バックアップ処理を使用する。

共通で既知の`/private/var`と`/var`だけを統一し、各既存親を`lstat`してリンク・非ディレクトリを拒否する。読み取り時のキャッシュフォルダのdevice/inodeと各ファイルの完全な属性スナップショットを保持し、適用時にも照合する。

## テーマと画像

`.passthm`はZIPとして読む。同じ構造の`.zip`も可。ZIPリーダーは壁紙用の既存実装を共用し、stored / Deflate、CRC、ローカルヘッダー一致、パス・重複・リンク・暗号化等の拒否を維持する。ディスクへ展開せず、必要な画像だけを読む。

認識する名前の例：

```text
1.png
2.jpg
other-1---white.png
other-2-A B C--mask.png
ru-5-М Н О П--white-bold.png
other-7-P Q R S-hi-white.png
```

`0`〜`9`、`*`、`#`に対応。TelephonyUIのwhite / mask、通常 / bold、ハイライトの候補を区別する。元テーマに対象の完全一致名があれば優先し、なければ同じキーの外観・言語・太字・ハイライトが近い画像を選ぶ。同条件ではテーマ内のTelephonyUI-10、9、8の順、その後にパス順で一意に決める。これは外部テーマの形式互換であり、端末のロック画面キャッシュを読む機能ではない。言語が違ってもキー番号は変えない。バージョン・正規化後の画像名が同じ候補の重複は拒否する。

端末上で確認できた各言語・外観・太字の画像へ反映するが、未生成のバリアントまでは作成しない。white画像しかないテーマ等ではmaskにも同じキーの画像が使われることがあり、外観が作者の想定と異なる可能性がある。

ImageIOで静止画像を読み、向きを補正して中央基準のaspect-fillで端末の既存PNGの幅・高さに自動調整し、任意の円形マスクを行って実際のPNGに変換する。サイズ指定APIも廃止し、外観・太字等で寸法が違っていても各ファイルの元寸法を保つ。円形マスクは短辺を直径とする中央の円で、非正方形の画像でもキャンバスを縮めたり楕円へ引き伸ばしたりしない。JPEGの拡張子を変えただけのデータを書き込まない。キーごとのパン／ズーム、壁紙一枚のシームレス分割、編集中のテーマの書き出し、キャッシュの全消去は実装しない。プレビューは240 pxの参考表示で、実際のレイアウト・背景・大きさ・合成と一致する保証はない。

制限：

- テーマZIP 128 MiB・2,000項目、取り込む画像512枚・合計128 MiB。
- 単一画像16 MiB・最大20,000 px辺・1億画素・1フレーム。画像デコードは最大2500 pxへ縮小する。
- 端末キャッシュは1フォルダ10,000項目、認識するPNGは合計1,500ファイル。
- 変更画像は単一最大2500×2500 px・16 MiB、変更データ合計256 MiB。
- UIが保持する編集元画像（テーマ＋個別画像）は合計128 MiB。

## バックアップ・適用・復元

### 既存画像の保存

「既存画像を保存」で、読み込んだ電話アプリのPNGを一覧から個別に保存できる。「一覧の画像をまとめて保存（ZIP）」では、電話の各言語・外観・太字・ハイライトの元ファイルをすべて保存する。キーを長押し→「このキーの既存画像を保存」では、そのキーに一覧を限定できる。

- 書き出すのは**現在の端末ファイルの完全なバイト列**であり、480 / 240 pxのプレビュー、インポートしたテーマ、個別画像の下書き、サイズや円形マスクの設定は使用しない。適用済みなら現在の適用後画像が対象になる。過去の適用前画像はバックアップ画面から別に確認・復元する。
- 読み取り前後の完全な属性スナップショットと親フォルダのdevice/inodeを照合する。ファイルが外部で変更された場合は保存を中止し、再読み込みを促す。複数ファイルの走査はOS全体の原子的スナップショットではない。
- 読み取りはManagerへのファイル単位の非同期要求で行い、権限を解放してから私有作業フォルダへコピーする。元キャッシュへの書き込み、書き込み確認要求、バックアップ作成は行わない。ZIP生成も私有コピーだけを読む。
- 一括ZIPの構造は`Data/TelephonyUI-10/<元の画像名>.png`、ファイル名は`Keypad-phone-images.zip`。端末コンテナのUUID等の絶対パスは含めない。既存の`.zip`テーマ読み取りでも再インポート可能。端末のフォルダ全体や認識対象外のファイルは含めない。
- 私有コピーのURLだけを`UIDocumentPickerViewController(forExporting:asCopy: true)`に渡し、「ファイル」で保存先を選ぶ。権限付き元URLを外部へ渡さず、アプリが選択先へ直接書き込むこともない。
- 単一16 MiB、合計256 MiB、1,500画像まで。ZIP上限は元画像上限＋2 MiB。読み取り失敗・変更検出・中止ではその要求専用の作業フォルダだけを削除し、不完全なZIPを渡さない。保存先ピッカーには完了までコピーを保持し、完了・キャンセル・画面終了後に通常の作業用データを整理する。プロセス強制終了時の即時削除は保証しない。

### 端末への適用

適用確認は既存の`fileWriteConfirmation`を使用する。Managerが専用の一回限りの変更計画を保持し、同意なし・キャンセル済み・バックグラウンド等で失効した要求は実行しない。通常の`prepareWrite(.replaceKeypad)`から専用検証を迂回することはできない。

1. 全対象のパス・親の識別情報・ファイル属性、書き込み用のno-follow openを検証する。
2. **全ファイルの永続バックアップが完了するまで1件も変更しない。** 個々のバックアップは既存のバイト比較・SHA-256検証・manifest同期を行う。元データ合計も256 MiBまで。
3. バックアップ後にも全対象が変わっていないことを検証する。
4. ファイルごとにno-follow openし、device/inode・完全スナップショットと元の全バイトを比較する。元inode・所有者・権限・xattrを保ち、PNGを書き込み・truncate・同期する。
5. 個別に完了結果を記録する。**一括処理は原子的ではない。** 途中の書き込み失敗・キャンセル・完了記録失敗では失敗を返し、完了件数と作成したバックアップIDを示す。現在処理中のファイルが部分的に変更された可能性もある。自動巻き戻しは行わない。

アクセスセッションは読み取り要求ごとに終了し、UIや走査actorで権限を保持しない。実際の一括バックアップ・書き込みだけは共通Managerの同期セッション内で直列実行し、内部にawaitを置かない。進行中のOSファイル操作を強制中断するものではない。

「バックアップ・元の画像を復元」から`TelephonyUI`で絞り込んで、対象ファイルを元の画像へ戻す。同じファイルを何度も変更した場合は、目的の時点の記録を選ぶ。復元も確認と現在データの再バックアップを行う。ファイル単位の復元であり、一括のテーマリセットではない。

### 反映

- 電話：電話アプリを開いて外観を切り替えるか、端末を再起動する。Erosionの案内に沿い、電話アプリの強制終了を反映手段として勧めない。
- 自動再起動・自動リスプリングは実行しない。

`Tests/KeypadExportTests.swift`ではPNGの完全なバイト列・寸法保持、元ファイルの不変性、電話の全バリアントのZIP格納と再インポート、非対応バージョンの保存拒否、読み取り失敗・キャンセル時の整理、変更・重複の拒否、所有していないディレクトリを削除しないことを確認する。実際の「ファイル」ピッカー操作はホストテストでは実行しない。
